# قرارداد چیدمان، RTL و لایه‌بندی رابط

این سند قرارداد اجرایی رابط فعلی بازی است. پیش از تغییر صفحه‌های موجود یا ساخت صفحهٔ جدید در `scripts/main.gd` خوانده شود.

## اصل پایه

بازی فارسی است، اما بوم مختصات رابط **LTR** است. این دو موضوع مستقل‌اند:

- مختصات، `position`، `size`، `anchor` و `offset` با بوم مرجع `1280×720` و از چپ به راست نوشته می‌شوند.
- متن فارسی با `text_direction = Control.TEXT_DIRECTION_RTL` و معمولاً `horizontal_alignment = HORIZONTAL_ALIGNMENT_RIGHT` نمایش داده می‌شود.
- در ابتدای `_ready()`، ریشهٔ صحنه با `layout_direction = Control.LAYOUT_DIRECTION_LTR` تثبیت شده است. این خط را حذف یا به RTL تغییر ندهید.

قرار دادن RTL روی کنترل والد برای «فارسی کردن» صفحه باعث آینه‌شدن مختصات در Android می‌شود. نتیجهٔ شناخته‌شدهٔ آن `position.x` منفی، پنل خارج از صفحه و ناحیهٔ لمس نامنطبق است.

## ساخت کنترل‌های دارای مختصات

برای هر `Control` که با `position` یا `offset` جای‌گذاری می‌شود:

1. پیش از تعیین موقعیت، `layout_direction = Control.LAYOUT_DIRECTION_LTR` را صریح تنظیم کنید.
2. اگر کنترل متن فارسی دارد، جداگانه `text_direction = Control.TEXT_DIRECTION_RTL` را تنظیم کنید.
3. برای دکمه‌ها و کنترل‌هایی که در Android با موقعیت منفی ظاهر شده‌اند، پس از `add_child()` نیز `position` را دوباره تعیین کنید. نمونهٔ فعلی: دکمه‌های دفتر کارآگاه.
4. هرگز مقدار عددی جهت چیدمان (مانند `1` یا `2`) را hard-code نکنید؛ فقط از ثابت‌های `Control.LAYOUT_DIRECTION_*` استفاده کنید.

الگوی پیشنهادی:

```gdscript
var label := Label.new()
label.layout_direction = Control.LAYOUT_DIRECTION_LTR
label.text_direction = Control.TEXT_DIRECTION_RTL
label.horizontal_alignment = HORIZONTAL_ALIGNMENT_RIGHT
parent.add_child(label)
label.position = Vector2(600, 150)
label.size = Vector2(360, 42)
```

## پنل‌ها و صفحه‌های تمام‌صفحه

- پنل‌های مرکزی از anchor `0.5` و offsetهای متقارن استفاده کنند.
- یک لایه که با تصویر پس‌زمینهٔ کامل هم‌مختصات است (مانند دفتر کارآگاه) باید `Control.PRESET_FULL_RECT` بگیرد، نه یک کنترل کوچکِ center-anchored.
- متن و دکمه‌های آن لایه با مختصات صریح نسبت به بوم `1280×720` قرار گیرند.
- پس از هر تغییر، هم نمایش و هم ناحیهٔ لمس روی گوشی واقعی بررسی شود؛ دیده‌شدن یک دکمه به‌تنهایی کافی نیست.

## هات‌اسپات‌ها و ترتیب لایه‌ها

قواعد z-index فعلی در `build_scene()` و `build_hotspots()`:

| لایه | z-index | کاربرد |
| --- | ---: | --- |
| تصویر پس‌زمینه | `-20` | هنر صحنه |
| سایهٔ صحنه | `-10` | تیره‌کردن ملایم صحنه |
| نقطه‌ها و ناحیه‌های لمس سرنخ | `-5` | بالای تصویر، زیر رابط |
| هدر، فوتر، دیالوگ‌ها، پنل‌ها و متن‌ها | `0` یا بالاتر | همیشه بالای هات‌اسپات |

هات‌اسپات‌ها به‌صورت `top_level` و با مختصات مرجع `1280×720` ساخته می‌شوند. موقعیت جهانی آن‌ها پس از `add_child()` تنظیم می‌شود. این ترتیب را حفظ کنید؛ در غیر این صورت ممکن است هم نشانگر و هم مستطیل لمس از جای درست جدا شوند.

## چک‌لیست پیش از تحویل UI

- متن فارسی RTL و راست‌چین است، ولی والدِ دارای مختصات LTR است.
- هیچ `global_rect` یا `position.x` منفیِ ناخواسته‌ای وجود ندارد.
- هات‌اسپات‌ها روی پنل/متن دیده نمی‌شوند و لمس پشت پنل منتقل نمی‌شود.
- صفحهٔ ۱۶:۹ مرجع و گوشی واقعی هر دو بررسی شده‌اند.
- پس از هر تغییر GDScript، اعتبارسنجی headless پروژه اجرا شده است.
